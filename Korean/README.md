# ROS-e 자판

**Roman Orthographic Simultaneous-input for English**\
영어 철자 기반 동시입력\
by eekdland (Sinseiki)

*별칭: ROSE*

  <img src="../images/ros-e_layout.png" width="640">

ROS-e는 영어를 위한 실험적인 동시입력 방식입니다.

기존의 속기 시스템과 달리 ROS-e는 일반적인 타자에서 사전, 브리프(brief), 음성학적 이론을 필요로 하지 않습니다. 단어의 철자를 직접 입력하여 출력할 수 있으므로, 특별한 속기 코드를 암기하지 않고도 생소한 단어, 식별자, 전문 용어, 신조어를 입력할 수 있습니다.
ROS-e는 사전 없이 사용할 수 있습니다.

이 프로젝트는 영어 문자 입력에 대한 다음과 같은 다른 접근법을 연구합니다.

-   음성 기반 입력 대신 철자 기반 입력
-   표준 키보드에서의 동시 글쇠 입력
-   철자와 출력의 직접적인 대응
-   일반 단어를 사전 없이 입력
-   적응형 동시입력 깊이
-   Onset--Nucleus--Coda 구조
-   각 그룹 내부에서 왼쪽에서 오른쪽으로 정렬
-   식별자와 전문 용어 입력을 고려한 개발자 친화적 입력

ROS-e는 한국어 동시입력 자판 연구, 특히 세모이 자판과 세벌식 기반 설계에서 영감을 받았습니다.

세벌식은 초성(Onset), 중성(Nucleus), 종성(Coda)을 서로 다른 입력 그룹으로 분리하는 한국어 자판 계열입니다.

핵심 아이디어는 단어의 자연스러운 철자 순서를 유지하면서 여러 글자를 함께 입력할 수 있도록 하는 것입니다.

이 프로젝트는 현재 AutoHotkey 프로토타입으로서 **Alpha** 단계에 있습니다.
(AutoHotkey 코드는 AI의 도움을 받아 작성되었습니다.)

실사용 시험이 계속됨에 따라 배열, 입력 규칙, 글쇠 배치는 변경될 수 있습니다.

현재 배열은 약 1,000만 자의 영어 텍스트를 반복적으로 분석한 뒤, 실제 타자 실험과 반복적인 개선을 거쳐 개발되었습니다.

# 왜 ROS-e를 쓰는가?

대부분의 영어 속기 시스템은 음성학적 이론, 사전, 암기한 속기 형태에 의존하여 높은 입력 압축률을 달성합니다.

ROS-e는 다른 방향을 탐구합니다. ROS-e는 전문 속기 시스템과 직접 경쟁하는 것을 목표로 하지 않습니다.

대신 철자와 입력 사이의 직접적인 대응 관계를 유지하면서, 표준 키보드에서 실용적인 타자 효율 향상을 제공하는 것을 목표로 합니다.

목표는 일반적인 타자와 완전한 속기 시스템 사이의 중간 영역을 만드는 것입니다.

단어를 속기 코드로 변환하는 대신, ROS-e는 동시입력을 허용하면서도 영어의 원래 철자 구조를 보존하려고 합니다.

# ROS-e 활성화 및 비활성화

ROS-e는 Scroll Lock을 기본 모드 전환 글쇠로 사용합니다.

-   Scroll Lock ON → ROS-e 활성화
-   Scroll Lock OFF → ROS-e 비활성화
-   F9 → 대체 전환 글쇠

따라서 Scroll Lock 표시등을 ROS-e의 현재 상태를 보여주는 시각적 표시로 사용할 수 있습니다.

ROS-e가 비활성화되어 있을 때에는 모든 글쇠가 현재 활성화된 기존 키보드 배열에 따라 정상적으로 동작합니다.

# 철자 순서 보존

ROS-e는 각 글쇠를 누르는 시점이 완벽하게 일치하지 않더라도 의도한 철자 순서를 보존하려고 합니다.

예:

``` text
researchTeam
cambridgeUniversity
humanMind
```

ROS-e의 동시입력 조합(chord)은 개별 글쇠가 눌린 정확한 시간 순서가 아니라 의도된 글자 순서에 따라 해석됩니다.

이 방식은 필요한 글자가 모두 들어 있지만 글자의 순서가 뒤바뀌는 [Transposed Letter
Effect](https://www.mrc-cbu.cam.ac.uk/people/matt.davis/cmabridge/)로 알려진 일반적인 타자 오류 유형을 줄이는 데 도움이 될 수 있습니다.

소프트웨어 개발자에게 다음과 같은 오류는

``` text
resaerchTeam
cambrigdeUniversity
huamnMind
```

코드 검토와 디버깅 과정에서 의외로 발견하기 어려울 수 있습니다.

ROS-e는 동시입력 조합 내부의 철자 순서를 보존함으로써 빠르게 타자할 때 이러한 오류가 발생할 가능성을 낮추는 것을 목표로 합니다.

------------------------------------------------------------------------

# 설계 철학

ROS-e는 다음 원칙을 바탕으로 합니다.

1.  철자를 우선합니다.
2.  동시입력은 읽고 예측할 수 있는 상태를 유지해야 합니다.
3.  사용자는 사전을 찾아보지 않고도 생소한 단어를 입력할 수 있어야
    합니다.
4.  약어는 필수가 아니라 선택 사항이어야 합니다.
5.  특별한 하드웨어 없이 표준 키보드를 사용할 수 있어야 합니다.

그리고 현재 ROS-e 배열은 기존 속기 배열에서 파생되지 않았습니다.

대신 약 1,000만 자의 영어 텍스트를 반복적으로 분석하고, 실제 타자 실험과 반복적인 배열 수정을 병행하여 글쇠 배치를 개발했습니다.

목표는 기존 속기 이론을 재현하는 것이 아니라, 표준 키보드에서 실용적으로 사용할 수 있으면서 영어 철자 순서를 보존하는 동시입력 시스템을 탐구하는 것이었습니다.

속기를 대체하려는 것이 아니라, 일반적인 타자와 완전한 속기 시스템 사이의 실용적인 중간 영역을 탐구하는 것입니다.

# 운지 철학

ROS-e는 엄격하게 고정된 손가락 배정을 전제로 하지 않습니다.

많은 기존 키보드 배열과 달리, ROS-e는 동시입력 중 불편한 손 움직임을 줄이기 위해 어느 정도 유연한 운지를 허용합니다.

## 양손 공유 모음

모음 영역은 양손이 공유합니다.

사용자는 특정 동시입력 조합에서 어느 손이 더 편한지에 따라 사용할 손을 선택할 수 있습니다.

따라서 같은 모음도 상황에 따라 왼손이나 오른손으로 입력할 수 있습니다.

## 유연한 운지

ROS-e는 대체로 일반적인 터치 타이핑 원칙을 따릅니다.

그러나 동시입력에서는 불편한 손 움직임이나 손가락 충돌을 줄일 수 있다면 다른 운지법을 사용할 수 있습니다.

목표는 하나의 운지법을 엄격하게 지키는 것이 아니라 실제 사용에서 편안하게 입력하는 것입니다.

어떤 동시입력 조합이 불편하다면, 더 자연스러운 손 움직임을 만들 수 있을 경우 인접한 손가락을 사용할 수 있습니다.

목표는 고정된 타법을 강제하는 것이 아니라 불필요한 부담을 최소화하는 것입니다.

## 엄지손가락 사용

엄지손가락은 일반적으로 사용할 필요가 없습니다.

그러나 ROS-e에서는 다음과 같은 경우 상황에 따라 엄지손가락을 사용할 수 있습니다.

-   엄지를 사용하지 않으면 동시입력 조합에서 손가락끼리 충돌하는 경우
-   짧은 손가락을 뻗는 동시에 긴 손가락을 구부려야 하는 경우 ('ac', 'al', 'li', 'mi', 'ur', 'ar' 등등.)
-   동시입력 조합 때문에 손을 지나치게 넓게 벌려야 하는 경우
-   엄지를 사용한 움직임이 훨씬 더 편안한 경우

따라서 엄지손가락 사용은 필수가 아니라 선택적이며 상황에 따라 달라집니다.

실제로 동시입력 때문에 손이 불편하거나 지나치게 벌어진 자세가 될 경우, 부담을 줄이기 위해 엄지손가락을 사용할 수 있습니다.

## 실용적이고 인체공학적인 손가락 사용

ROS-e는 이론적인 손가락 배정보다 실제 사용에서의 편안함을 우선합니다.

여러 운지가 가능하다면, 의도한 철자 순서를 유지하면서 가장 자연스러운 움직임이 나오는 방법을 선택하는 것을 권장합니다.

# Onset Shift와 Coda Shift

ROS-e에는 **Onset Shift**와 **Coda Shift**라는 두 가지 방식이 있습니다.

영어에는 26개의 알파벳이 있지만 동시입력에서는 여러 위치 그룹이 필요하므로, 글자를 세 가지 기능적 범주로 구분합니다.

-   Onset
-   Nucleus
-   Coda

ROS-e는 Onset, Nucleus, Coda 그룹을 각각 처리하여 단어를 재구성합니다.
왼쪽에서 오른쪽으로의 정렬은 동시입력 조합 전체가 아니라 각 그룹 내부에서 적용됩니다.

Onset Shift와 Coda Shift는 Onset과 Coda 그룹이 표현할 수 있는 글자의 범위를 확장합니다.

이를 통해 Onset--Nucleus--Coda 구조와 철자 순서를 유지하면서, 사용할 수 있는 글쇠 위치만으로는 담기 어려운 더 많은 글자를 ROS-e에서 표현할 수 있습니다.

------------------------------------------------------------------------

# 모음 설계

영어에는 다음과 같이 흔히 사용되는 여러 글자짜리 모음 조합이 많습니다.

``` text
ee
ea
oo
ou
ie
oi
```

이러한 패턴을 효율적으로 지원하기 위해 ROS-e는 일부 모음에 중복된 모음 위치를 사용합니다.

이 설계는 철자상의 일관성을 유지하면서 흔한 모음 조합을 자연스럽게 입력할 수 있도록 합니다.

# 선택적 약어

ROS-e에는 자주 사용하는 단어를 입력하는 데 필요한 글쇠 수를 줄이는 것을 주된 목적으로 하는 선택적 물리 글쇠 동시입력 약어 시스템이 포함되어 있습니다.

일반적인 ROS-e 입력에는 약어가 필요하지 않습니다. 단어, 식별자 및 그 밖의 임의 문자열은 약어 사전에 의존하지 않고도 철자를 통해 직접 입력할 수 있습니다.

기본 약어 세트는 **A+X(Q)** 계열의 물리 글쇠 조합을 사용합니다. 이는 배포되는 기본 약어에서 사용하는 관례일 뿐이며, 약어 시스템 자체의 제한이 아닙니다.

어떤 동시입력 조합을 약어로 지정하면 그 조합의 일반적인 ROS-e 출력이 덮어써지므로, 일반적인 영어 철자에서 유용한 글자열을 나타낼 가능성이 낮은 조합을 선택하는 것이 좋습니다.

이러한 이유로 배포되는 기본 약어는 **U가 없는 Q**에 해당하는 조합을 사용합니다. 일반적인 영어 철자에서 Q는 대부분 U와 함께 사용되므로, U가 포함되지 않은 Q 조합은 일반적인 철자 입력에 대한 간섭을 줄이면서 선택적 약어에 활용하기에 비교적 적합한 공간을 제공합니다.

이는 기본 약어 세트의 설계상 선택일 뿐입니다. 사용자는 자신의 필요에 따라 기본 약어를 변경하거나 삭제하거나 다른 약어로 교체할 수 있습니다.

또한 사용자는 **어떤 물리 글쇠 동시입력 조합**에든 텍스트를 지정하여 약어를 추가할 수 있습니다. 어떤 조합이 약어로 지정되면 해당 조합은 그 약어를 위해 예약되며, 그 조합을 통한 원래 ROS-e 출력은 더 이상 사용할 수 없습니다. 따라서 사용자는 자신만의 약어 조합을 선택할 때 일반적인 ROS-e 입력과 충돌할 가능성을 고려해야 합니다.

약어는 해당 글쇠가 일반적으로 출력하는 글자가 아니라 물리 글쇠 자체를 기준으로 일치 여부를 판단합니다. 따라서 약어 정의는 ROS-e의 Onset, Nucleus, Coda 해석과 독립적으로 유지됩니다.

약어 정의에서 글쇠를 적는 순서는 상관없습니다. 동시입력 조합 ID는 자동으로 정규화(canonicalize)되므로, 동일한 물리 글쇠 조합을 서로 다른 순서로 적어도 같은 조합으로 처리됩니다.

이 기능의 목적은 ROS-e를 사전 의존적인 속기 시스템으로 만드는 것이 아닙니다. 직접적인 철자 입력을 핵심 방식으로 유지하면서, 사용자가 직접 제어할 수 있는 선택적 입력 압축 계층을 제공합니다.

## 기본 내장 약어

이 단어들은 개발자들이 자주 사용하는 단어를 기반으로 선택한 기본 내장 약어입니다.
기본 약어는 활용이 자유로운 기본형을 원칙으로 하였습니다.
( https://zenodo.org/records/285293 )

(QWERTY 물리 글쇠)

-  a + x + k → return
-  a + x + l → function
-  a + x + ; → public
-  a + x + y → import
-  a + x + u → void
-  a + x + i → array
-  a + x + o → static
-  a + x + p → true
-  a + x + / → false
<br />

- a + x + k + ; → private
- a + x + l + ; → break
- a + x + y + ; → double
- a + x + u + ; → class
- a + x + i + ; → final
- a + x + o + ; → protect
- a + x + p + ; → boolean
- a + x + m + ; → struct
- a + x + / + ; → extends

# 보조키와 단축키

ROS-e는 대문자 입력이나 시스템 단축키를 위해 별도의 방식을 도입하지 않습니다.

Shift, Ctrl, Alt 또는 Win을 누르면 ROS-e는 일시적으로 기존 키보드 배열의 입력을 사용합니다.

따라서 사용자는 별도의 단축키 규칙을 배우지 않고도 익숙한 키보드 동작을 계속 사용할 수 있습니다.

예:

-   Shift + 글자 → 대문자
-   Ctrl + C → 복사
-   Ctrl + V → 붙여넣기
-   Ctrl + Z → 실행 취소
-   Alt + Tab → 작업 전환
-   Win + R → 실행 창
-   Win + E → 파일 탐색기

이 방식은 기존 단축키에 대한 간섭을 최소화하면서 ROS-e를 운영체제 및 개발 도구의 기존 작업 흐름과 함께 사용할 수 있도록 합니다.

------------------------------------------------------------------------

# 문장 부호

일부 ROS-e 글자 배정은 원래 문장 부호에 사용되는 글쇠 위치를 사용합니다.

따라서 일부 문장 부호는 보조키를 사용하여 입력해야 할 수 있습니다.

예:

-   Shift + ; → ;
-   Shift + ; 두 번 → :
-   Shift + / → /
-   Shift + / 두 번 → ?

정확한 동작 방식은 향후 개발 과정에서 변경될 수 있습니다.

------------------------------------------------------------------------

# 향후 계획

ROS-e는 사전이나 속기 시스템 없이도 완전하게 사용할 수 있도록 설계되었습니다.

향후 개발에서는 추가적인 생산성 기능, 실험적인 입력 방식 또는 선택적 확장 기능을 검토할 수 있습니다.

향후 개발의 구체적인 방향은 아직 확정되지 않았습니다.

------------------------------------------------------------------------

# 결론

ROS-e는 일반적인 타자와 기존 속기 사이의 중간 영역에 위치하는 철자 기반 동시입력 시스템으로 볼 수 있습니다.
